1. Objetivo y alcance

Este documento registra el proceso de publicación de StockVelia como aplicación web accesible por internet, orientada a pequeños negocios como tiendas, minimercados y misceláneas. Describe las plataformas utilizadas, las configuraciones identificadas en las capturas de Vercel y Render, y el estado funcional informado durante las pruebas (no se recibieron capturas del panel de Supabase).

2. Arquitectura desplegada y estructura del repositorio

La arquitectura separa la interfaz, la lógica del servidor y el almacenamiento de datos: el navegador carga la aplicación en Vercel (React), el frontend envía solicitudes a la API en Render (Node.js + Express) y el backend consulta o modifica los datos en Supabase (PostgreSQL).

Capa Plataforma / Tecnología Función en el sistema
Frontend Vercel · React Publica la interfaz web con la que interactúa el usuario.
Backend Render · Node.js + Express Ejecuta el servidor y expone los endpoints de la API.
Base de datos Supabase · PostgreSQL Administra la base de datos relacional utilizada por el backend.

En el repositorio jaiderovalle6 / StockVelia (rama main), Vercel detecta una estructura tipo monorepo con carpetas separadas para backend y frontend, lo que permite configurar la carpeta raíz correspondiente en cada plataforma.

5.1 Incidente SMTP en Render Free

Al probar la recuperación de contraseña con Nodemailer y la cuenta stockvelia7@gmail.com hacia smtp.gmail.com (probando puerto 465 con secure: true y luego puerto 587 con secure: false y family: 4), los logs de Render reportaron ENETUNREACH y Connection timeout. Render restringe el SMTP saliente en servicios gratuitos para los puertos 25, 465 y 587, por lo que cambiar puerto o forzar IPv4 no resuelve la restricción de red del plan.

  • Opción 1: Mantener Render Free e integrar un proveedor de correo vía API HTTPS (como Resend, verificando dominio para envío a cualquier usuario en producción).
  • Opción 2: Evaluar un plan de pago en Render que permita SMTP saliente y conservar Nodemailer con Gmail, verificando precios y condiciones vigentes.

6. Seguridad, lista de verificación y datos pendientes

  • Seguridad: No subir secretos ni archivos .env al repositorio (usar .gitignore), no exponer secretos de Supabase o JWT en el frontend, restringir CORS a los orígenes necesarios, evitar imprimir tokens o contraseñas en logs y redesplegar tras cambiar variables de entorno.
  • Checklist pendiente de validar: Confirmar Root Directory y comandos finales de build/start en Render, verificar CORS hacia Vercel, probar registro e inicio de sesión en producción y validar la recuperación de contraseña con el proveedor de correo definitivo.
