1. Arquitectura general y requisitos previos

StockVelia está estructurado como una aplicación web multi-empresa compuesta por tres capas principales: una base de datos relacional PostgreSQL (con tablas multi-tenant, restricciones CHECK, índices y trigger automático de stock), un Backend en Node.js / Express (autenticación JWT, revocación de sesión en lista negra, control de roles, transacciones con bloqueo de fila, carga de avatares y envío de correos) y un Frontend en React (interfaz por rol, selector de empresa, tema dinámico, filtros avanzados y exportación a PDF/CSV).

1.1 Requisitos del entorno y herramientas necesarias

Componente / Herramienta Función en el despliegue Verificación mínima
Node.js (LTS) y npm Ejecución del servidor API Express, instalación de dependencias y compilación/servidor del Frontend React. node -v y npm -v funcionales en terminal.
PostgreSQL Almacenamiento transaccional de empresas, usuarios, categorías, productos, movimientos, códigos de recuperación, blacklist y auditoría. Servicio PostgreSQL activo y acceso mediante psql o cliente SQL.
Git Clonación del repositorio y control de versiones de código fuente y scripts SQL. git --version disponible.
Cuenta / Servidor SMTP Envío de códigos de recuperación de contraseña de 6 dígitos mediante Nodemailer. Host SMTP, puerto, usuario y clave/contraseña de aplicación válidos.

2. Instalación y preparación de la base de datos PostgreSQL

Antes de iniciar la API, crea la base de datos y aplica el esquema, las restricciones, los índices, el trigger de stock y los roles iniciales:

  1. Verificar que el servicio PostgreSQL esté en ejecución: asegúrate de que el motor esté arriba y escucha en el puerto configurado (habitualmente 5432).
  2. Crear la base de datos de StockVelia: conéctate con psql (por ejemplo con usuario postgres) y crea la base de datos: 
    CREATE DATABASE stockvelia;
\c stockvelia
  3. Ejecutar el script de estructura, trigger e índices: aplica el archivo SQL del proyecto que define:
    • Tablas: roles, empresa, usuario, usuario_empresa, categorias, productos, movimientos_inventario, codigos_recuperacion, tokens_blacklist y auditoria.
    • Restricciones de integridad: precios y stocks no negativos, justificación obligatoria en bajas/daños (chk_justificacion_baja) y estados válidos.
    • Trigger y función de actualización atómica de stock (trg_actualizar_stock) e índices de consulta.
    psql -U postgres -d stockvelia -f database/schema.sql
  4. Sembrar los roles base del sistema: verifica que existan exactamente los tres roles esperados por el código: 
    INSERT INTO public.roles (id_rol, nombre) VALUES
  (1, 'Propietario'),
  (2, 'Administrador Operativo'),
  (3, 'Empleado')
ON CONFLICT (id_rol) DO NOTHING;

3. Instalación y arranque del Backend (Node.js / Express)

  1. Ubícate en la carpeta del backend e instala dependencias: 
    cd backend
npm install
  2. Crea y configura el archivo .env a partir de la plantilla de entorno del proyecto (ver Sección 5).
  3. Verifica la carpeta de subida de avatares: asegúrate de que exista y tenga permisos de lectura/escritura la ruta destinada a las fotografías de perfil subidas por POST /api/usuarios/perfil/foto.
  4. Inicia el servidor Backend: 
    npm run dev   # o npm start según scripts configurados en package.json

4. Instalación y arranque del Frontend (React)

  1. Ubícate en la carpeta del frontend e instala dependencias: 
    cd frontend
npm install
  2. Configura la URL base de la API: define la variable de entorno del frontend apuntando al backend (por ejemplo, en .env o .env.local según tu configuración de bundler).
  3. Inicia el servidor de desarrollo o compila para producción: 
    npm run dev      # Entorno de desarrollo
npm run build    # Generación de artefactos estáticos para producción

5. Variables de entorno, CORS, SMTP y carga de archivos

Revisa que todas estas variables y parámetros estén correctamente definidos antes de operar:

Parámetro / Variable Propósito en StockVelia Observación importante
Datos de conexión PostgreSQL Host, puerto, nombre de BD (stockvelia), usuario y contraseña para el pool de conexión. Usar credenciales con privilegios adecuados sobre la base de datos del sistema.
JWT_SECRET Firma y verificación de tokens JWT emitidos al iniciar sesión (vigencia de 2h). Debe ser una clave robusta y mantenerse privada en el servidor.
FRONTEND_URL y CORS Define los orígenes permitidos para peticiones cross-origin desde el frontend React. Si hay múltiples orígenes, sepáralos o configúralos según el parser de CORS del backend.
Variables SMTP / Correo Envío de códigos de 6 dígitos (vigencia de 15 minutos) para recuperación de contraseña vía Nodemailer. Sin credenciales SMTP válidas, el flujo de recuperación por correo fallará.
Límite y formatos de avatar Multer acepta image/jpeg, image/jpg, image/png y image/webp hasta 2 MB. Verifica que el directorio de destino sea accesible tanto en escritura como en lectura.

6. Verificación post-instalación

Completa esta lista de comprobación para confirmar que la instalación quedó lista:

  1. Registro inicial: Registra una empresa de prueba y verifica que el usuario inicial quede con rol Propietario (1) y que se registre auditoría.
  2. Login y bloqueo: Inicia sesión con credenciales válidas, prueba el cierre de sesión (verificando invalidación del token en tokens_blacklist) y valida el bloqueo tras 5 intentos fallidos.
  3. Catálogo y movimiento: Crea una categoría y un producto, registra una ENTRADA y una SALIDA/BAJA, y comprueba que el trigger actualice el stock y que una BAJA sin justificación sea rechazada.
  4. Multi-empresa y reportes: Vincula o crea una segunda empresa con el mismo correo de Propietario, alterna desde el selector de empresa y descarga un reporte en PDF y CSV.

7. Solución de problemas comunes

  • Error de conexión a PostgreSQL: Verifica que el servicio PostgreSQL esté iniciado, que el puerto y credenciales coincidan con el entorno y que la base de datos stockvelia exista.
  • Error CORS o 401/403 en peticiones desde el navegador: Revisa que FRONTEND_URL incluya el origen exacto donde corre React y que la cabecera Authorization: Bearer <token> se envíe en rutas protegidas.
  • Fallo al subir foto de perfil: Confirma que el archivo sea JPG, JPEG, PNG o WEBP, no supere los 2 MB y que el directorio de subida tenga permisos de escritura.
  • Correo de recuperación no llega: Revisa los datos SMTP, el puerto/TLS y la carpeta de spam; recuerda que el código de 6 dígitos expira a los 15 minutos.
Listo para producción o pruebas: Una vez superadas estas verificaciones, conserva tus copias de respaldo según el Entregable 04 (Plan de respaldo) y mantén protegido el archivo de variables de entorno.
